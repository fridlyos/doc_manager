## API transaction fix

`test_patch_requires_and_checks_if_match` + `test_jobs_list_get_cancel` previously failed after
`Problem` exceptions unwound through `async with session.begin()`, leaving intermittent pooled
connection failures on later requests.

Implemented: mutating API routes now use autobegin + explicit `session.commit()`, matching the
job engine. Handled integrity failures explicitly roll back before returning 409.

PG rerun (2026-07-15) surfaced two final bugs, both fixed:

1. `jobs.py` retry route: `replayed` unset on the non-replay branch → `UnboundLocalError`.
2. MissingGreenlet root cause: `updated_at` uses a server-side `onupdate`; SQLAlchemy
   `eager_defaults="auto"` fetches RETURNING on INSERT only, so ORM UPDATE left the column
   expired and the serializer's attribute access triggered a sync lazy load. Fixed with
   `__mapper_args__ = {"eager_defaults": True}` on `SourceLocation` and `CatalogEntry`.

## SQLAlchemy lessons learned (applied in engine and routes)

1. `session.get()` after raw-SQL UPDATE returns stale identity-map object → use `populate_existing=True`.
2. Prefer autobegin + explicit `session.commit()` over `async with session.begin()` — reads autobegin a txn and make `begin()` raise "already begun".
3. Mutate all ORM fields before helper queries — autoflush pushes half-mutated rows (lease CHECK violation in reaper was this).
